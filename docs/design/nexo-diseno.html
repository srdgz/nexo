5

Flujos de usuario

Regla común: una operación fallida nunca se muestra como exitosa. En finanzas no hay actualizaciones optimistas.

F-01 · Registro y verificación

flowchart TD
  A[auth/register] --> B{Formulario válido?}
  B -- No --> B1[Errores bajo cada campo] --> A
  B -- Sí --> C[signUp con nombre, email, contraseña e idioma]
  C -- Email ya registrado --> C1[Ya existe una cuenta + enlace a login] --> A
  C -- OK --> D[auth/verify-email]
  D --> E[Abre el enlace del correo]
  E --> F[auth/callback canjea el código]
  F -- Enlace caducado --> F1[Error + Reenviar enlace] --> D
  F -- OK --> G[Trigger crea perfil y 12 categorías]
  G --> H[Dashboard con estado vacío guiado]

F-02 · Login, ruta protegida y sesión caducada

flowchart TD
  A[Abre app/finances/budgets] --> B{authGuard: sesión válida?}
  B -- No --> C[auth/login con returnUrl]
  C --> D[signInWithPassword]
  D -- Credenciales incorrectas --> D1[Email o contraseña incorrectos] --> C
  D -- Email sin verificar --> D2[Aviso + Reenviar enlace] --> C
  D -- OK --> E[Vuelve a la ruta pedida]
  B -- Sí --> E
  E --> F[El refresh del token falla]
  F --> G[Se limpian los stores + toast Tu sesión ha caducado] --> C

F-03 · Recuperar contraseña

flowchart TD
  A[auth/forgot-password] --> B[resetPasswordForEmail]
  B --> C[Mensaje neutro: si existe la cuenta recibirás un correo]
  C --> D[Abre el enlace]
  D --> E{Sesión de recovery?}
  E -- No --> F[El enlace ha caducado + pedir otro] --> A
  E -- Sí --> G[auth/reset-password: nueva + repetir]
  G --> H[Contraseña actualizada → dashboard]

F-06 · Registrar un gasto

flowchart TD
  A[Nuevo → Gasto · móvil: ＋ → Gasto] --> B[transactions/new?type=expense]
  B --> C[Importe, categoría, fecha, descripción, tarea opcional]
  C --> D{Válido?}
  D -- No --> C
  D -- Sí --> E[Guardar en estado de carga]
  E -- Error --> E1[Toast de error, datos conservados] --> C
  E -- OK --> F[El store recarga el periodo]
  F --> G[Toast Gasto registrado + vuelta al origen]
  G --> H{Supera 80 % o 100 % del presupuesto?}
  H -- Sí --> I[El toast avisa: has usado el 92 % de Alimentación]

F-08 · El nexo: tarea con pago previsto

flowchart TD
  A[Nueva tarea: Pagar seguro del coche] --> B[Vence 20 nov · prioridad alta]
  B --> C[Pago previsto: 350,00 € · Transporte]
  C --> D[Aparece en Tareas y en Próximos pagos]
  D --> E[Marca la tarea como completada]
  E --> F{Pago previsto sin movimiento?}
  F -- No --> G[Toast Tarea completada]
  F -- Sí --> H[Diálogo: ¿Registrar el pago de 350,00 €?]
  H -- Ahora no --> G
  H -- Registrar --> I[Formulario de gasto relleno y enlazado]
  I --> J[Guardar → balance y presupuesto actualizados]

F-12 · Eliminar con confirmación

flowchart TD
  A[Menú de fila → Eliminar] --> B[ConfirmDialog con nombre e importe]
  B -- Cancelar --> Z[Sin cambios]
  B -- Eliminar --> C[Botón en carga, diálogo bloqueado]
  C -- Error --> D[Mensaje dentro del diálogo, el elemento sigue]
  C -- OK --> E[Se quita de la lista + toast]
  A2[Categoría con movimientos] --> F[Eliminar desactivado: se ofrece Archivar]
F-07 · Presupuesto

Presupuestos → «Nuevo presupuesto» → diálogo (móvil: hoja) con categorías de gasto sin presupuesto ese mes → guardar. Duplicado → error en el campo. Mes vacío → «Copiar de octubre».

F-09 · Completar y filtrar tareas

El check muestra carga hasta la confirmación; si falla, vuelve atrás con un toast. Filtros por estado y prioridad guardados en la URL.

F-10 · Evento desde el calendario

Clic en un día → evento con 09:00–10:00 por defecto → «el fin debe ser posterior al inicio» → vuelve al día seleccionado.

F-11 · Cambio de periodo

El selector de mes cambia ?month; cada tarjeta del dashboard carga y falla por separado, con «Reintentar» propio.

6

Modelo de datos definitivo

Seis tablas, todas con RLS. La propiedad de los registros relacionados se garantiza con claves foráneas compuestas (id, user_id): PostgreSQL rechaza usar la categoría o la tarea de otra persona sin necesidad de triggers. El SQL completo está en docs/06-modelo-datos.md.

RLS

Una política por operación y tabla para authenticated con (select auth.uid()) = user_id; anon sin acceso. user_id toma por defecto auth.uid(), el frontend no lo envía.

Lecturas agregadas

finance_summary, expenses_by_category, monthly_trend y budget_progress como funciones security invoker: el dashboard no descarga todos los movimientos.
